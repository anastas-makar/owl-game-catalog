# Здания

Каждый JSON-файл в этой директории описывает один шаблон здания вместе с его комнатами и прилегающими участками.

Здания размещаются в городе на освобождённой карте. В зданиях могут жить животные.

Здания бывают двух типов:

* `HOUSE` — дом;
* `FORTRESS` — замок.

`FORTRESS` — техническое название типа в каталоге. В интерфейсе такое здание называется замком.

Внутри здания находятся комнаты. В комнатах можно размещать мебель. Если в комнате установлен холодильник, животное может готовить блюда из припасов по известным рецептам.

Возле каждого дома есть огород, в котором можно выращивать растения.

Возле каждого замка есть огород, сад и пруд. В саду и пруду можно размещать соответствующие предметы.

## Главное

* Один файл — одно здание.
* Имя файла совпадает с корневым `templateId`.
* Комнаты и прилегающие участки являются вложенными частями здания.
* Здание импортируется целиком, даже если изменена только одна комната или один участок.
* Стабильный `templateId` комнаты или участка позволяет отличить редактирование от удаления и создания нового элемента.
* В доме должна быть хотя бы одна комната.
* В замке должно быть хотя бы две комнаты.
* У дома должен быть один огород и не должно быть сада или пруда.
* У замка должны быть огород, сад и пруд.

## Полный пример замка

```json
{
  "templateId": "stone-fortress",
  "name": "Каменный замок",
  "type": "FORTRESS",
  "cost": 5000,
  "sourceImageUrl": "https://example.org/stone-fortress.png",
  "rooms": [
    {
      "templateId": "main-hall",
      "name": "Главный зал",
      "roomNumber": 10,
      "sourceImageUrl": "https://example.org/main-hall.png"
    },
    {
      "templateId": "kitchen",
      "name": "Кухня",
      "roomNumber": 20,
      "sourceImageUrl": "https://example.org/kitchen.png"
    }
  ],
  "gardens": [
    {
      "templateId": "kitchen-garden",
      "name": "Огород",
      "gardenNumber": 10,
      "gardenType": "KITCHEN_GARDEN",
      "sourceImageUrl": "https://example.org/kitchen-garden.png"
    },
    {
      "templateId": "main-garden",
      "name": "Сад",
      "gardenNumber": 20,
      "gardenType": "GARDEN",
      "sourceImageUrl": "https://example.org/main-garden.png"
    },
    {
      "templateId": "pond",
      "name": "Пруд",
      "gardenNumber": 30,
      "gardenType": "POOL",
      "sourceImageUrl": "https://example.org/pond.png"
    }
  ]
}
```

В рабочей ветке вместо `imageKey` можно использовать временный публичный `sourceImageUrl`.

Перед публикацией каталога временные ссылки заменяются на `imageKey`.

## Поля здания

### `templateId`

Обязательный стабильный идентификатор шаблона здания.

```json
{
  "templateId": "stone-fortress"
}
```

`templateId`:

* должен быть непустой строкой;
* должен быть уникален среди всех зданий;
* сохраняется при редактировании существующего здания.

Изменение `templateId` означает удаление старого шаблона и добавление нового.

### `name`

Обязательное название здания, отображаемое игроку.

```json
{
  "name": "Каменный замок"
}
```

### `type`

Тип здания.

Допустимые значения:

* `HOUSE` — дом;
* `FORTRESS` — замок.

Тип влияет на минимальное количество комнат и набор прилегающих участков.

### `cost`

Стоимость здания в бриллиантах.

```json
{
  "cost": 5000
}
```

Замок должен быть заметно дороже дома.

Пока баланс не зафиксирован окончательно, можно ориентироваться на такие значения:

* дома — примерно от `700` до `1500` бриллиантов;
* замки — примерно от `4500` до `5500` бриллиантов.

Эти диапазоны являются ориентиром для баланса, а не частью формата каталога. При изменении экономики игры их можно пересматривать без изменения `schemaVersion`.

### Изображение здания

У здания должно быть изображение.

В рабочей ветке:

```json
{
  "sourceImageUrl": "https://example.org/stone-fortress.png"
}
```

В опубликованном каталоге:

```json
{
  "imageKey": "buildings/stone-fortress.webp"
}
```

Не указывайте `imageKey` и `sourceImageUrl` одновременно.

## Комнаты

Комнаты описываются в массиве `rooms`.

Каждая комната содержит:

* стабильный `templateId`;
* отображаемое `name`;
* `roomNumber`;
* изображение.

Пример:

```json
{
  "templateId": "kitchen",
  "name": "Кухня",
  "roomNumber": 20,
  "sourceImageUrl": "https://example.org/kitchen.png"
}
```

В доме должна быть хотя бы одна комната.

В замке должно быть хотя бы две комнаты.

### `templateId` комнаты

`templateId` определяет саму комнату и сохраняется при её редактировании.

Например, если кухня стала называться «Большая кухня», идентификатор сохраняется:

```json
{
  "templateId": "kitchen",
  "name": "Большая кухня"
}
```

Замена `kitchen` на другой `templateId` означает удаление старой комнаты и добавление новой.

Идентификаторы комнат должны быть уникальны внутри одного здания.

### `roomNumber`

`roomNumber` задаёт порядок отображения комнат.

Мобильное приложение сортирует комнаты по `roomNumber`.

Номер не является идентификатором комнаты и не обязан начинаться с `1`.

Допустимы пропуски:

```text
10, 20, 30
```

так же хорошо работают, как:

```text
1, 2, 3
```

Это позволяет при необходимости вставить новую комнату между существующими без перенумерации всего здания.

`roomNumber` должен быть целым числом. Номера комнат внутри одного здания не должны повторяться, чтобы порядок был однозначным.

Изменение `roomNumber` меняет положение существующей комнаты в галерее, но не создаёт новую комнату.

### Изображение комнаты

У каждой комнаты должно быть изображение.

В рабочей ветке можно использовать `sourceImageUrl`, а перед публикацией он заменяется на `imageKey`.

## Огород, сад и пруд

Прилегающие участки описываются в массиве `gardens`.

Название `gardens` является техническим: в этом массиве хранятся не только сады, но также огороды и пруды.

Каждый участок содержит:

* стабильный `templateId`;
* отображаемое `name`;
* `gardenNumber`;
* `gardenType`;
* изображение.

Допустимые значения `gardenType`:

* `KITCHEN_GARDEN` — огород;
* `GARDEN` — сад;
* `POOL` — пруд.

### Правила для дома

У здания типа `HOUSE` должен быть огород:

```json
{
  "gardenType": "KITCHEN_GARDEN"
}
```

В текущей модели у дома должен быть один участок, и его тип должен быть `KITCHEN_GARDEN`.

У дома не должно быть участков типа `GARDEN` или `POOL`.

### Правила для замка

У здания типа `FORTRESS` должны быть три участка:

* один `KITCHEN_GARDEN`;
* один `GARDEN`;
* один `POOL`.

Например:

```json
{
  "gardens": [
    {
      "templateId": "kitchen-garden",
      "name": "Огород",
      "gardenNumber": 10,
      "gardenType": "KITCHEN_GARDEN",
      "sourceImageUrl": "https://example.org/kitchen-garden.png"
    },
    {
      "templateId": "main-garden",
      "name": "Сад",
      "gardenNumber": 20,
      "gardenType": "GARDEN",
      "sourceImageUrl": "https://example.org/main-garden.png"
    },
    {
      "templateId": "pond",
      "name": "Пруд",
      "gardenNumber": 30,
      "gardenType": "POOL",
      "sourceImageUrl": "https://example.org/pond.png"
    }
  ]  
}
```

### `templateId` участка

`templateId` участка сохраняется при его редактировании.

Идентификаторы участков должны быть уникальны внутри одного здания.

### `gardenNumber`

`gardenNumber` задаёт порядок отображения участков после комнат.

Мобильное приложение сортирует участки по `gardenNumber`.

Номер не обязан начинаться с `1`, и в последовательности допустимы пропуски.

Например:

```text
10, 20, 30
```

`gardenNumber` должен быть целым числом. Номера участков внутри одного здания не должны повторяться, чтобы порядок был однозначным.

Изменение `gardenNumber` меняет положение существующего участка в галерее, но не меняет его идентичность.

### Изображение участка

У каждого огорода, сада и пруда должно быть изображение.

В рабочей ветке можно использовать `sourceImageUrl`, а перед публикацией он заменяется на `imageKey`.

## Источники получения

Здания поддерживают стандартное поле `allowedAcquisitionSources`.

Если здание можно получать любым поддерживаемым способом, поле можно не указывать:

```json
{
  "templateId": "small-house"
}
```

Если здание доступно только через определённые источники, укажите белый список:

```json
{
  "allowedAcquisitionSources": [
    "QUEST_REWARD"
  ]
}
```

Пустой список означает, что здание нельзя получить ни одним стандартным способом:

```json
{
  "allowedAcquisitionSources": []
}
```

Подробнее о семантике источников получения см. в [общем README каталога](../README.md#acquisition-sources).

## Изображения

Изображение должно быть у:

* самого здания;
* каждой комнаты;
* каждого огорода, сада и пруда.

В рабочем pull request допустим `sourceImageUrl`.

После переноса изображения в основное S3 используется `imageKey`.

Пример:

```json
{
  "imageKey": "buildings/stone-fortress/kitchen.webp"
}
```

Не указывайте оба поля одновременно.

## Проверка перед pull request

Перед pull request проверьте:

* имя файла совпадает с `templateId` здания;
* `name`, `type` и `cost` указаны;
* `type` равен `HOUSE` или `FORTRESS`;
* у здания есть изображение;
* у дома есть хотя бы одна комната;
* у замка есть хотя бы две комнаты;
* у всех комнат есть `templateId`, `name`, `roomNumber` и изображение;
* `templateId` комнат не повторяются внутри здания;
* `roomNumber` комнат не повторяются внутри здания;
* у дома есть ровно один участок типа `KITCHEN_GARDEN`;
* у дома нет `GARDEN` и `POOL`;
* у замка есть по одному участку `KITCHEN_GARDEN`, `GARDEN` и `POOL`;
* у всех участков есть `templateId`, `name`, `gardenNumber`, `gardenType` и изображение;
* `templateId` участков не повторяются внутри здания;
* `gardenNumber` участков не повторяются внутри здания;
* `gardenType` указан правильно: `KITCHEN_GARDEN` — огород, `GARDEN` — сад, `POOL` — пруд;
* `cost` подобран с учётом стоимости других зданий;
* временные `sourceImageUrl` публично доступны;
* UUID игровых экземпляров и другие пользовательские данные отсутствуют;
* перед публикацией все `sourceImageUrl` заменены на `imageKey`.
