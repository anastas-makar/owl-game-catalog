# Рецепты

Каждый файл описывает один рецепт, его результат и необходимые ингредиенты.

Рецепты следует делать простыми: ингредиенты попадаются игроку с определённой вероятностью, поэтому длинный список компонентов будет сложно собрать.

Обычно рецепт должен содержать не более двух ингредиентов. В исключительных случаях допускается три ингредиента.

Базовые вещи, такие как вода, соль и масло для жарки, лучше не указывать. Предполагается, что они всегда есть у игрока в необходимом количестве.

Не рекомендуется использовать в качестве ингредиентов припасы, которые сами готовятся по рецептам. Исключение составляют несколько заранее определённых базовых ингредиентов.

Общие правила находятся в [`catalog/README.md`](../README.md).

## Базовые составные ингредиенты

Некоторые припасы готовятся по рецептам, но затем могут использоваться в других рецептах.

В частности, они нужны для приготовления зелий, которые наносят урон:

* Звёздная вода;
* Солнечная вода;
* Огненная слеза.

Этот список пока не окончательный. Перед добавлением нового составного ингредиента следует проверить, действительно ли он нужен нескольким рецептам. Не стоит создавать длинные цепочки, в которых для приготовления одного предмета сначала требуется приготовить несколько других.

## Пример структуры

```json
{
  "templateId": "pumpkin-soup",
  "name": "Тыквенный суп",
  "description": "Нужна тыква и молоко.",
  "resultSupplyTemplateId": "pumpkin-soup-supply",
  "ingredients": [
    {
      "supplyTemplateId": "pumpkin",
      "amount": 2
    },
    {
      "supplyTemplateId": "milk",
      "amount": 1
    }
  ]
}
```

Поля должны соответствовать структуре, показанной в примере выше.

## Результат

`resultSupplyTemplateId` должен ссылаться на существующий припас
из [`../supplies/`](../supplies/).

Рецепт всегда даёт один тип припаса. Количество получаемого припаса всегда равно 1.

## Ингредиенты

Каждый ингредиент должен ссылаться на существующий `supplyTemplateId`.

`amount` должен быть положительным целым числом.

Не следует случайно добавлять один и тот же припас в список ингредиентов несколько раз:

```json
{
  "ingredients": [
    {
      "supplyTemplateId": "pumpkin",
      "amount": 1
    },
    {
      "supplyTemplateId": "pumpkin",
      "amount": 1
    }
  ]
}
```

Вместо этого количество следует объединить:

```json
{
  "ingredients": [
    {
      "supplyTemplateId": "pumpkin",
      "amount": 2
    }
  ]
}
```

## Источники получения

Рецепты могут выпадать из мешочка, появляться в лавке торговца и выдаваться за завершение квеста или экспедиции.

Если рецепт можно получить любым способом, поле `allowedAcquisitionSources` указывать не нужно.

Пример рецепта, доступного только в мешочке и лавке:

```json
{
  "templateId": "pumpkin-soup",
  "allowedAcquisitionSources": [
    "POUCH",
    "SHOP"
  ]
}
```

Подробнее о белом списке и значениях `POUCH`, `SHOP` и `QUEST_REWARD` см. в разделе [«Источники получения»](../README.md#acquisition-sources).

## Выдача рецепта за квест

Чтобы выдать конкретный рецепт за завершение квеста, укажите его `templateId` в `recipeLoot` конечной страницы:

```json
{
  "endingId": "cookbook-found",
  "lootButtonText": "Забрать рецепт",
  "lootBundle": {
    "recipeLoot": {
      "templateIds": [
        "pumpkin-soup"
      ],
      "amount": 1
    }
  }
}
```

Если у рецепта задан белый список `allowedAcquisitionSources`, он должен содержать `QUEST_REWARD`.

## Проверка

Перед pull request проверьте:

* `templateId` рецепта уникален;
* `resultSupplyTemplateId` ссылается на существующий припас;
* все ингредиенты существуют;
* список `ingredients` не пуст;
* `amount` каждого ингредиента является положительным целым числом;
* один ингредиент не указан несколько раз;
* рецепт не содержит лишних базовых компонентов;
* рецепт обычно требует не более двух, в исключительном случае — трёх ингредиентов;
* составные ингредиенты используются только при необходимости;
* значения `allowedAcquisitionSources` существуют в enum backend.
