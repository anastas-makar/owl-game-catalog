# Карты

Каждый файл описывает один шаблон карты и расположенные на ней слоты локаций и врагов.

## Карты в игре

В игре карты находятся в разделе "Мои владения". 

Первая карта, которая выпадает игроку, всегда свободна, потому что без свободной карты невозможно играть. 

На свободной карте можно основать город. В городе можно строить дома и замки. В домах и замках могут селиться животные.

Также на карте могут быть локации (описание локаций в разделе [`../locations/`](../locations/)). 

Некоторые локации, как правило, природного происхождения, выпадают случайным образом и приходят вместе с картой. 

Для таких локаций в шаблоне карты указываются `locationSlots`. 

Если `locationSlots` расставлены и ограничены правильно, на карте не возникнет аномалий вроде появления руин в воде или водопада в лесу. 

Для этого слоты могут ограничивать допустимые типы локаций.

Другие локации игрок может строить в городе самостоятельно. В этом случае он сам решает, что и где размещать. 

Дома и замки в городах можно объединять в улицы. 

Можно выбирать мэра города среди животных, которые живут в этом городе. Мэр города может жить как в замке, так и в домике.

Города можно объединять в страны. Можно выбирать правителя страны среди животных, которые живут в этой стране.

Правитель страны обязательно должен жить в замке. 

Все карты, кроме первой, оккупированы врагами. Описание врагов есть в разделе [`../enemies/`](../enemies/). 

Для врагов в шаблоне карты указываются `enemySlots`. 

Смысл слотов врагов тот же, что и у слотов локаций: они защищают от аномалий. Враги выбираются случайным образом и размещаются в подходящих слотах на карте. 

Чтобы освободить оккупированную карту, нужно отправить животное в экспедицию, снабдив его достаточным количеством припасов, чешуек и бомбочек, которые дают очки атаки и защиты.

Общие правила работы с каталогом находятся в [`catalog/README.md`](../README.md).

## Пример

```json
{
  "templateId": "swamp-map",
  "name": "Болотистая местность",
  "sourceImageUrl": "https://example.org/swamp-map.png",
  "completionMedalTemplateId": "swamp-liberator",
  "completionLootBundle": {
    "diamondLoot": {
      "amount": 20
    }
  },
  "locationSlots": [],
  "enemySlots": []
}
```

В опубликованном каталоге вместо `sourceImageUrl` используется `imageKey`. Подробнее см. общие правила работы с изображениями в [`catalog/README.md`](../README.md).

## Слоты

Слот — не самостоятельный шаблон каталога. Он описывает стабильное место внутри конкретной карты, поэтому использует `slotId`, а не `templateId`.

`slotId` должен быть уникален в пределах соответствующего массива слотов одной карты.

Один и тот же `slotId` может использоваться в разных картах.

После публикации карты `slotId` считается стабильным. Если параметры слота изменились, но `slotId` сохранился, это изменение существующего слота. Если старый `slotId` исчез и появился новый, это удаление одного слота и добавление другого.

## Слоты локаций

Локации, которые создаются сразу как часть карты, размещаются в `locationSlots`. 

Такой экземпляр уже находится на карте и не требует строительства игроком.

`allowedAcquisitionSources` шаблона локации на заполнение `locationSlots` не влияет: это поле относится только к получению локации отдельно от карты.

Слот может либо указывать конкретную локацию, либо ограничивать случайный выбор подходящими типами локаций.

### Фиксированная локация

```json
{
  "slotId": "north-grotto",
  "mode": "FIXED",
  "x": 0.2,
  "y": 0.35,
  "fixedLocationTemplateId": "old-grotto"
}
```

Если mode равен FIXED, `fixedLocationTemplateId` должен ссылаться на существующую локацию из [`../locations/`](../locations/).

### Ограничение по типу

Для случайно выбираемых локаций слот может ограничивать допустимые типы через `allowedTypes`.

Например:

```json
{
    "slotId": "waterfall-slot",
    "mode": "RANDOM",
    "x": 0.6,
    "y": 0.25,
    "allowedTypes": [
      "WATERFALL"
    ]
}
```

Такой слот подходит только для локаций типа `WATERFALL`.

Если указано несколько значений allowedTypes, для слота может быть выбрана локация любого из перечисленных типов.

Если ограничение по типу не требуется, allowedTypes можно не указывать.

Типы локаций имеют игровой смысл и используются мобильным приложением, в частности для выбора иконки локации на карте.

### Типы локаций

Доступные типы локаций:

* `PARK` — парк;
* `MONUMENT` — памятник;
* `LANDMARK` — достопримечательность;
* `PAVILION` — шатёр;
* `CAVE` — пещера;
* `FOUNTAIN` — фонтан;
* `RESORT` — курорт;
* `WATERFALL` — водопад;
* `RUINS` — руины;
* `WATER_ANOMALY` — водная аномалия.

## Слоты врагов

Пример:

```json
{
  "slotId": "north-gate",
  "x": 0.25,
  "y": 0.4,
  "requiredTags": [
    "swamp"
  ]
}
```

`requiredTags` ограничивает выбор врагов по их техническим тегам.

## Координаты

`x` и `y` задают положение слота на карте.

Координаты задаются в диапазоне от 0 до 1, то есть, в долях от единицы. Длина и ширина карты равны 1.

## Награда за освобождение карты

Экспедиция всегда является освобождением карты. Одну карту можно успешно освободить только один раз, поэтому награда за её освобождение также выдаётся только один раз.

Каждая карта обязательно содержит:

* медаль за освобождение в `completionMedalTemplateId`;
* лут за освобождение в `completionLootBundle`.

### Медаль

```json
{
  "completionMedalTemplateId": "swamp-liberator"
}
```

`completionMedalTemplateId` должен ссылаться на существующую медаль из [`../medals/`](../medals/).

Подробнее о медалях см. в [документации медалей](../medals/README.md).

### Лут

Лут за успешное завершение экспедиции задаётся через `completionLootBundle`.

Например:

```json
{
  "completionLootBundle": {
    "diamondLoot": {
      "amount": 20
    }
  }
}
```

`completionLootBundle` должен содержать хотя бы одну награду.

Шаблоны, указанные в `completionLootBundle`, должны быть доступны через источник `EXPEDITION_REWARD`.

Полная структура `lootBundle`, правила случайного выбора, `amount` и `dropChance` описаны в [документации лута](../LOOT.md).

## Источники получения карты

Сама карта является игровой сущностью и может быть получена различными стандартными способами.

Если способы получения карты требуется ограничить, используется `allowedAcquisitionSources`.

Подробнее см. раздел [«Источники получения»](../README.md#acquisition-sources).

## Проверка

Перед pull request проверьте:

* `templateId` карты уникален среди карт;
* `slotId` непусты и уникальны в пределах соответствующего массива;
* фиксированные локации ссылаются на существующие шаблоны локаций;
* значения `allowedTypes` в слотах локаций соответствуют существующим типам локаций;
* для каждого случайного слота локации существует хотя бы одна подходящая локация;
* для каждого слота врага существует хотя бы один враг, соответствующий всем `requiredTags`;
* координаты соответствуют системе координат карты;
* `completionMedalTemplateId` указан и ссылается на существующую медаль;
* `completionLootBundle` указан, не пуст и соответствует правилам [`LOOT.md`](../LOOT.md);
* шаблоны из `completionLootBundle` доступны через `EXPEDITION_REWARD`;
* значения `allowedAcquisitionSources`, если они указаны, являются допустимыми источниками получения;
* изображение передано через `sourceImageUrl` или `imageKey`, а не добавлено бинарным файлом в репозиторий.
