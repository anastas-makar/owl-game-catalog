# Враги

Каждый JSON-файл описывает один шаблон врага.

Враги — это существа, которые появляются на оккупированной карте и противостоят животному игрока во время экспедиции.

Чтобы освободить карту, животное должно победить всех врагов в текущей экспедиции.

Для этого животному должно хватить очков атаки и защиты для последовательной победы над всеми врагами.

Враги разбросаны по карте и вступают в бой по очереди. 

В интерфейсе игрок видит характеристики животного и текущего противника; характеристики ещё не встреченных врагов заранее не показываются.

Во время каждого боя очки атаки и защиты животного и активного врага постепенно расходуются. 

После победы над одним врагом животное переходит к следующему с оставшимися запасами атаки и защиты.

Карту можно успешно освободить только один раз. После победы враги на ней больше не появляются.

Проигрывать экспедицию можно много раз. После поражения создаётся новая экспедиция, и для неё заново выбираются враги.

Таким образом, шаблон карты содержит только `enemySlots`, определяющие возможное размещение врагов, а конкретный набор врагов относится к созданной экспедиции.

Подробнее о картах, экспедициях и `enemySlots` см. в [`../maps/README.md`](../maps/README.md).

Общие правила работы с каталогом находятся в [`catalog/README.md`](../README.md).

## Полный пример

```json
{
  "templateId": "swamp-ghoul",
  "name": "Болотный упырь",
  "description": "Слабый болотный противник.",
  "sourceImageUrl": "https://example.org/swamp-ghoul.png",
  "health": 120,
  "damage": 50,
  "tags": [
    "swamp",
    "weak"
  ]
}
```

В рабочей ветке вместо `imageKey` можно использовать временный публичный `sourceImageUrl`.

Перед публикацией каталога временные ссылки заменяются на `imageKey`.

## Поля врага

### `templateId`

Обязательный стабильный идентификатор шаблона врага.

```json
{
  "templateId": "swamp-ghoul"
}
```

`templateId`:

* должен быть непустой строкой;
* должен быть уникален среди всех врагов;
* сохраняется при редактировании существующего врага.

Изменение `templateId` означает удаление старого шаблона и добавление нового.

### `name`

Обязательное название врага, отображаемое игроку.

```json
{
  "name": "Болотный упырь"
}
```

### `description`

Обязательное описание врага.

```json
{
  "description": "Слабый болотный противник."
}
```

### Изображение

Враг должен иметь изображение.

В рабочей ветке допускается:

```json
{
  "sourceImageUrl": "https://example.org/swamp-ghoul.png"
}
```

В опубликованном каталоге используется:

```json
{
  "imageKey": "enemies/swamp-ghoul.webp"
}
```

Не следует одновременно указывать `imageKey` и `sourceImageUrl`.

## Боевые характеристики

У врага есть две основные боевые характеристики:

* `health` — здоровье врага;
* `damage` — наносимый врагом урон.

Пример:

```json
{
  "health": 120,
  "damage": 50
}
```

Враги сражаются с животным по очереди. Во время боя постепенно расходуются очки атаки и защиты животного и активного врага. 

Если заканчиваются очки атаки животного, животное больше не может атаковать и экспедиция заканчивается поражением. 

Если заканчиваются очки защиты, животное больше не может защищаться и также терпит поражение.

Если заканчиваются очки атаки или защиты врага, враг побеждён, и животное переходит к следующему, либо побеждает, если врагов больше нет.

Поэтому результат экспедиции зависит не просто от суммы характеристик всех врагов. 

При подборе характеристик следует учитывать длительность боя. 

Если у врага много очков атаки, но мало очков защиты, он может быть быстро побеждён, а оставшиеся очки атаки не будут использованы в игре.

Сильно несбалансированные значения health и damage могут давать неожиданный игровой эффект, поэтому обычно стоит ориентироваться на пропорции уже существующих врагов.

Не добавляйте дополнительные боевые характеристики, которых нет в актуальной модели врага.

## Теги

У врагов нет фиксированных типов.

Для ограничения случайного выбора врагов используются технические теги в поле `tags`.

Например:

```json
{
  "tags": [
    "swamp",
    "weak"
  ]
}
```

Теги описывают свойства врага, которые могут понадобиться при заполнении слотов карты.

Теги:

* должны быть непустыми строками;
* не должны повторяться внутри одного врага;
* должны оставаться стабильными, пока используются картами;
* следует добавлять только тогда, когда у тега есть понятное игровое назначение.

В отличие от enum, список допустимых тегов заранее не фиксирован.

Если для врага специальные ограничения не нужны, `tags` можно не указывать или оставить пустым.

## Связь с картами

Шаблон карты не содержит конкретный набор врагов. Вместо этого он содержит `enemySlots`.

Слот может ограничивать случайный выбор врага с помощью `requiredTags`.

Например:

```json
{
  "slotId": "north-swamp",
  "x": 0.25,
  "y": 0.4,
  "requiredTags": [
    "swamp"
  ]
}
```

Такой слот может быть заполнен только врагом, у которого есть тег `swamp`.

Если указано несколько значений `requiredTags`, враг должен иметь все перечисленные теги.

Например:

```json
{
  "requiredTags": [
    "swamp",
    "weak"
  ]
}
```

такому слоту подходит враг:

```json
{
  "tags": [
    "swamp",
    "weak",
    "flying"
  ]
}
```

но не подходит враг:

```json
{
  "tags": [
    "swamp"
  ]
}
```

Если `requiredTags` отсутствует или равен `null`, слот может быть заполнен любым существующим врагом.

Для каждого `enemySlot` должен существовать хотя бы один враг, подходящий под ограничения этого слота.

Подробнее о слотах врагов см. в [`../maps/README.md`](../maps/README.md).

## Получение врагов

Враги не являются предметами игрока и не выдаются через стандартные источники получения.

Поле `allowedAcquisitionSources` для врагов не используется.

Конкретные враги выбираются backend при создании экспедиции согласно ограничениям `enemySlots` карты.

## Проверка

Перед pull request проверьте:

* `templateId` указан и уникален среди врагов;
* `name` и `description` указаны;
* изображение передано через `sourceImageUrl` или `imageKey`;
* `health` и `damage` заданы целыми числами и соответствуют игровому балансу;
* `tags`, если они указаны, являются непустыми строками и не повторяются;
* для каждого используемого в `enemySlots.requiredTags` набора тегов существует хотя бы один подходящий враг;
* поле `allowedAcquisitionSources` не используется;
* перед публикацией временные `sourceImageUrl` заменены на `imageKey`.
