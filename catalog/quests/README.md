# Квесты

Квест состоит из страниц. Каждая страница может показывать текст и изображение, предлагать варианты перехода, завершать квест, изменять сцену и выдавать награду.

Общие правила находятся в [`catalog/README.md`](../README.md).

## Основная структура

Упрощённый пример:

```json
{
  "templateId": "first-hatches",
  "name": "Первые люки",
  "startPageNumber": 1,
  "pages": [
    {
      "number": 1,
      "name": "Закрытый люк",
      "description": "Перед вами старый железный люк.",
      "options": [
        {
          "text": "Открыть люк",
          "targetPageNumber": 2
        },
        {
          "text": "Уйти",
          "targetPageNumber": 3
        }
      ]
    },
    {
      "number": 2,
      "name": "Подземелье",
      "description": "Под люком обнаружился тайный проход.",
      "endingId": "hatch-opened",
      "lootButtonText": "Забрать награду",
      "lootBundle": {
        "furnitureLoot": {
          "templateIds": [
            "quest-sword"
          ],
          "amount": 1
        },
        "plantLoot": {
          "amount": 1,
          "dropChance": 0.5
        }
      }
    },
    {
      "number": 3,
      "name": "Возвращение",
      "description": "Вы решили вернуться позже.",
      "endingId": "left-the-hatch"
    }
  ]
}
```

Названия дополнительных полей должны соответствовать текущим `CatalogQuestImport`, `CatalogQuestPageImport` и `CatalogQuestOptionImport`.

## Стартовая страница

`startPageNumber` должен совпадать с `number` одной из страниц.

## Номера страниц

`number`:

- обязателен для каждой страницы;
- уникален внутри квеста;
- используется в `targetPageNumber`;
- не является UUID и не заменяется случайно при редактировании.

Порядок страниц в JSON не должен использоваться вместо номера.

## Переходы

Каждая опция с `targetPageNumber` должна вести на существующую страницу того же квеста.

```json
{
  "text": "Продолжить",
  "targetPageNumber": 4
}
```

## Конечные страницы и endingId

Конечная страница имеет стабильный `endingId`:

```json
{
  "number": 7,
  "endingId": "owl-rescued"
}
```

`endingId` должен быть уникален внутри квеста. При редактировании прежней развязки сохраняйте его. Новый `endingId` означает новую развязку.

## Scene patch

`scenePatch` описывает изменение сцены, связанное с прохождением страницы. Поля внутри patch должны точно соответствовать актуальному `CatalogScenePatch`.

## Лут

`lootBundle` размещается в конечной странице с `endingId`.

`lootAvailable` в каталог не записывается. Доступность награды определяется для конкретного игрока backend-сервисом.

### Независимые пулы

Каждый присутствующий пул разыгрывается независимо.

```json
{
  "lootBundle": {
    "furnitureLoot": {
      "templateIds": [
        "quest-sword"
      ],
      "amount": 1
    },
    "plantLoot": {
      "amount": 1,
      "dropChance": 0.5
    },
    "diamondLoot": {
      "amount": 20
    }
  }
}
```

Это означает:

- квестовый меч выпадает гарантированно;
- с вероятностью 50% выпадает одно допустимое растение;
- 20 алмазов выдаются гарантированно.

### Поддерживаемые категории

Текущая модель `CatalogLootBundle` может содержать:

```text
buildingLoot
mapLoot
diamondLoot
gardenItemLoot
plantLoot
furnitureLoot
recipeLoot
locationLoot
```

Используйте точные имена полей текущего DTO.

### templateIds

```json
{
  "templateIds": [
    "red-sofa",
    "green-armchair"
  ]
}
```

означает случайный выбор одного из перечисленных шаблонов.

Если поле отсутствует или равно `null`, backend выбирает любой шаблон соответствующей категории, допустимый для `QUEST_REWARD`.

Пустой список запрещён:

```json
{
  "templateIds": []
}
```

### amount

`amount` — количество экземпляров выбранного шаблона. В текущей простой модели сначала выбирается один шаблон, затем выдаётся указанное количество его экземпляров.

Для алмазов `amount` означает количество алмазов.

### dropChance

`dropChance` — независимая вероятность выпадения пула от `0` до `1`.

```json
{
  "dropChance": 0.5
}
```

означает 50%. Отсутствующее поле или `null` означает гарантированное выпадение.

`dropChance` — не относительный вес и не количество попыток. В модели нет `rolls` и `withReplacement`.

## Кнопка награды

`lootButtonText` имеет смысл только при наличии `lootBundle`:

```json
{
  "lootButtonText": "Забрать награду"
}
```

## Ограничение источников

Сущность, доступная только в квесте, должна иметь в собственном файле:

```json
{
  "allowedAcquisitionSources": [
    "QUEST_REWARD"
  ]
}
```

Квестовый лут не должен ссылаться на сущность, белый список которой запрещает `QUEST_REWARD`.

## Проверка квеста

- `startPageNumber` существует;
- номера страниц уникальны;
- все `targetPageNumber` существуют;
- `endingId` уникальны;
- `lootBundle` находится на конечной странице;
- `lootButtonText` не существует без лута;
- `dropChance` находится от `0` до `1`;
- `amount` положителен;
- `templateIds` не пуст;
- все ссылки на шаблоны существуют;
- указанные награды доступны через `QUEST_REWARD`;
- временные ссылки на изображения открываются.
