# Локации

Каждый файл описывает одну локацию и вложенные в неё сцены.

Общие правила находятся в [`catalog/README.md`](../README.md).

## Пример структуры

```json
{
  "templateId": "old-grotto",
  "name": "Старый грот",
  "sourceImageUrl": "https://example.org/old-grotto.png",
  "scenes": [
    {
      "templateId": "entrance",
      "name": "Вход в грот"
    },
    {
      "templateId": "underground-hall",
      "name": "Подземный зал",
      "questTemplateId": "first-hatches"
    }
  ]
}
```

Дополните пример полями текущих `CatalogLocationImport` и `CatalogSceneImport`.

## Сцены

Каждая сцена должна иметь стабильный `templateId`, уникальный внутри локации.

Сохранение идентификатора означает редактирование существующей сцены. Замена идентификатора означает удаление старой и добавление новой.

## Связь с квестом

Если сцена запускает квест:

```json
{
  "questTemplateId": "first-hatches"
}
```

Указанный квест должен существовать в [`../quests/`](../quests/).

## Scene patch

Изменения сцены, происходящие на страницах квеста, описываются моделью `CatalogScenePatch`. Конкретные поля patch должны соответствовать актуальному DTO.

При изменении структуры patch одновременно обновите import DTO, каталожную Mongo-модель, mapper, Python-валидатор и документацию квестов.

## Проверка

- идентификаторы сцен уникальны в пределах локации;
- ссылки на квесты существуют;
- порядок сцен соответствует клиенту, если модель использует порядок;
- картинки переданы через `sourceImageUrl` или `imageKey`.
