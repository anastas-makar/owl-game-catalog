# Локации

Каждый JSON-файл описывает один шаблон локации и вложенные в него сцены.

Локации отображаются на карте и могут содержать дополнительные сцены с описаниями, изображениями и квестами.

Часть локаций появляется на карте автоматически. Например, это могут быть природные объекты, размещённые в `locationSlots` шаблона карты.

Другие локации игрок может построить самостоятельно, потратив количество бриллиантов, указанное в `buildPrice` локации.

Эти способы не обязательно взаимоисключающие: доступная для постройки локация также может использоваться в `locationSlots`, если подходит под ограничения слота.

Правила размещения локаций на картах описаны в [`../maps/README.md`](../maps/README.md).

Сцены в локациях могут содержать переход к квестам. Для этого нужно указать `templateId` квеста в поле `questTemplateId` сцены. 

Структура квестов описана в [`../quests/README.md`](../quests/README.md).

Общие правила работы с каталогом находятся в [`catalog/README.md`](../README.md).

## Полный пример

Пример локации, которая может быть добавлена на карту через `locationSlots` шаблона карты:

```json
{
  "templateId": "old-grotto",
  "name": "Старый грот",
  "description": "Старинный грот в склоне холма.",
  "sourceImageUrl": "https://example.org/old-grotto.png",
  "type": "CAVE",
  "buildPrice": null,
  "scenes": [
    {
      "templateId": "entrance",
      "name": "Вход в грот",
      "description": "Каменная лестница уходит в темноту.",
      "sourceImageUrl": "https://example.org/old-grotto-entrance.png",
      "sceneNumber": 1
    },
    {
      "templateId": "underground-hall",
      "name": "Подземный зал",
      "description": "За узким проходом находится большой подземный зал.",
      "sourceImageUrl": "https://example.org/old-grotto-hall.png",
      "sceneNumber": 2,
      "questTemplateId": "first-hatches",
      "questButtonText": "Осмотреть старый люк"
    }
  ],
  "allowedAcquisitionSources": []
}
```

Пример локации, которая может быть добавлена в инвентарь, а затем построена игроком:

```json
{
  "templateId": "city-fountain",
  "name": "Городской фонтан",
  "description": "...",
  "sourceImageUrl": "https://example.org/city-fountain.png",
  "type": "FOUNTAIN",
  "buildPrice": 50,
  "scenes": [
    {
      "templateId": "blue-water",
      "name": "Вода журчит",
      "description": "Пузырьки и брызги рассеивают свет.",
      "sourceImageUrl": "https://example.org/fountain-blue-water.png",
      "sceneNumber": 1
    },
    {
      "templateId": "fish-in-the-fountain",
      "name": "Здесь живут рыбы",
      "description": "Тени рыб мелькают на дне, но их сложно рассмотреть.",
      "sourceImageUrl": "https://example.org/fish-in-the-fountain.png",
      "sceneNumber": 2,
      "questTemplateId": "watch-fish",
      "questButtonText": "Попытаться рассмотреть рыб"
    }
  ],
  "allowedAcquisitionSources": [
    "SHOP",
    "QUEST_REWARD"
  ]
}
```

В рабочей ветке вместо `imageKey` можно использовать временный публичный `sourceImageUrl` согласно [общим правилам работы с изображениями](../README.md).

Перед публикацией каталога временные ссылки заменяются на `imageKey`.

## Поля локации

### `templateId`

Обязательный стабильный идентификатор шаблона локации.

```json
{
  "templateId": "old-grotto"
}
```

`templateId`:

* должен быть непустой строкой;
* должен быть уникален среди всех локаций;
* сохраняется при редактировании существующей локации.

Изменение `templateId` означает удаление старого шаблона и добавление нового.

### `name`

Обязательное название локации, отображаемое игроку.

```json
{
  "name": "Старый грот"
}
```

### `description`

Обязательное основное описание локации.

```json
{
  "description": "Старинный грот в склоне холма."
}
```

### Изображение

Локация должна иметь изображение.

В рабочей ветке автора допускается:

```json
{
  "sourceImageUrl": "https://example.org/old-grotto.png"
}
```

В опубликованном каталоге используется:

```json
{
  "imageKey": "locations/old-grotto.webp"
}
```

Не следует одновременно указывать `imageKey` и `sourceImageUrl`.

## Тип локации

Поле `type` обязательно и определяет тип локации.

```json
{
  "type": "CAVE"
}
```

Допустимые типы:

* `PARK` — парк;
* `MONUMENT` — памятник;
* `LANDMARK` — достопримечательность;
* `PAVILION` — шатёр;
* `CAVE` — пещера или грот;
* `FOUNTAIN` — фонтан;
* `RESORT` — курорт;
* `WATERFALL` — водопад;
* `RUINS` — руины;
* `WATER_ANOMALY` — водная аномалия.

Это не строгая смысловая классификация. 

Значение `type` должно быть одним из перечисленных выше, но используется прежде всего для технических нужд, 
в частности в мобильном приложении для выбора иконки локации на карте. 
Поэтому название типа не обязательно должно буквально описывать объект. 
Например, лагерь бродячих музыкантов можно отнести к `PAVILION`, а парк аттракционов — к `PARK`.

Тип также может использоваться слотами карты для ограничения случайного размещения локаций через `allowedTypes`.

Например, слот:

```json
{
  "allowedTypes": [
    "WATERFALL"
  ]
}
```

может быть заполнен только локацией типа `WATERFALL`.

Подробнее см. в [`../maps/README.md`](../maps/README.md).

## Стоимость строительства

`buildPrice` задаёт стоимость строительства локации игроком в бриллиантах.

```json
{
  "buildPrice": 50
}
```

Значения:

* `null` или отсутствующее поле — эту локацию нельзя построить самостоятельно;
* `0` — локацию можно построить бесплатно;
* положительное целое число — стоимость строительства в бриллиантах.

Природные локации, которые появляются на карте автоматически, обычно имеют:

```json
{
  "buildPrice": null
}
```

`buildPrice: null` или отсутствие `buildPrice` означает, что игрок не может построить локацию, и такая локация не должна попасть в инвентарь. 
У таких локаций следует указывать `allowedAcquisitionSources` в виде пустого массива `[]`.

Такая локация не попадёт в инвентарь отдельно, но может быть добавлена на карту автоматически через `locationSlots` карты. 
В этом случае игрок получает её уже размещённой и ничего не строит.

## Сцены

Поле `scenes` содержит дополнительные сцены локации.

```json
{
  "scenes": [
    {
      "templateId": "entrance",
      "description": "Вход в пещеру.",
      "sceneNumber": 1
    }
  ]
}
```

Сцены отображаются в галерее локации после основной карточки самой локации.

Массив может быть пустым, если у локации нет дополнительных сцен.

## `templateId` сцены

Каждая сцена имеет собственный стабильный `templateId`.

```json
{
  "templateId": "underground-hall"
}
```

Он должен быть:

* непустым;
* уникальным внутри данной локации;
* стабильным при редактировании существующей сцены.

`templateId` сцены является её идентификатором.

Порядок сцен определяется отдельно через `sceneNumber`.

## Нумерация сцен

`sceneNumber` — обязательное положительное целое число, определяющее порядок сцен в галерее.

```json
{
  "sceneNumber": 1
}
```

Сцены обычно нумеруются начиная с `1`.

Например:

```text
1, 2, 3
```

или:

```text
1, 5, 10
```

Оба варианта допустимы.

Требования:

* `sceneNumber` должен быть положительным целым числом;
* номера должны быть уникальны внутри одной локации;
* непрерывная нумерация не требуется;
* меньшее значение отображается раньше большего.

`sceneNumber` не является идентификатором сцены. При изменении порядка сцен разрешается менять их `sceneNumber`, не меняя `templateId`.

Основная карточка самой локации не входит в эту нумерацию и всегда отображается перед дополнительными сценами.

## Поля сцены

Сцена может иметь название:

```json
{
  "name": "Подземный зал"
}
```

Название необязательно.

Описание сцены обязательно:

```json
{
  "description": "За узким проходом находится большой подземный зал."
}
```

Сцена также должна иметь изображение:

```json
{
  "imageKey": "locations/old-grotto/underground-hall.webp"
}
```

В рабочей ветке вместо `imageKey` допускается временный `sourceImageUrl`.

## Связь сцены с квестом

Сцена может запускать квест.

Для этого используется `questTemplateId`:

```json
{
  "questTemplateId": "first-hatches"
}
```

Значение должно совпадать с `templateId` существующего квеста из [`../quests/`](../quests/).

Если `questTemplateId` отсутствует, сцена не запускает квест.

### Текст кнопки квеста

Для сцены с квестом можно указать собственный текст кнопки:

```json
{
  "questTemplateId": "first-hatches",
  "questButtonText": "Осмотреть старый люк"
}
```

`questButtonText` необязателен.

Если он отсутствует, мобильное приложение использует стандартный текст кнопки открытия квеста.

`questButtonText` не следует указывать без `questTemplateId`.

## Изменение сцены после квеста

Квест может изменить сцену локации после достижения определённой концовки.

Эти изменения задаются не в JSON локации, а через `scenePatch` на конечной странице квеста.

Например, после прохождения квеста закрытый люк может стать открытым.

Правила `scenePatch` описаны в [`../quests/README.md`](../quests/README.md).

## Источники получения

Для локации можно ограничить стандартные источники получения через `allowedAcquisitionSources`.

Локация, созданная вместе с картой через `locationSlots`, уже размещена на карте и в инвентарь не попадает. 

Поэтому поле `allowedAcquisitionSources` не влияет на заполнение `locationSlots` карты.

Пример для отдельной локации:

```json
{
  "allowedAcquisitionSources": [
    "QUEST_REWARD",
    "EXPEDITION_REWARD"
  ]
}
```

Общие правила и допустимые значения описаны в [разделе об источниках получения](../README.md#acquisition-sources).

Отсутствие `allowedAcquisitionSources` или значение `null` означает отсутствие ограничений.

Пустой массив означает, что локацию нельзя получить ни одним из стандартных источников, 
но она может быть размещена на карте автоматически.

## Проверка

Перед pull request проверьте:

* `templateId` локации указан и уникален среди локаций;
* `name` и `description` указаны;
* `type` соответствует одному из допустимых типов локаций;
* `buildPrice`, если указан, является неотрицательным целым числом;
* если `buildPrice` отсутствует или равен `null`, `allowedAcquisitionSources` равен `[]`;
* если локация должна выдаваться отдельно в инвентарь, у неё указан `buildPrice`;
* изображение передано через `sourceImageUrl` или `imageKey`;
* `templateId` каждой сцены указан и уникален внутри локации;
* `sceneNumber` каждой сцены является положительным целым числом;
* `sceneNumber` не повторяется внутри одной локации;
* описание и изображение каждой сцены указаны;
* каждый `questTemplateId` ссылается на существующий квест;
* `questButtonText` не указан без `questTemplateId`;
* значения `allowedAcquisitionSources`, если они указаны, являются допустимыми источниками получения;
* перед публикацией временные `sourceImageUrl` заменены на `imageKey`.
